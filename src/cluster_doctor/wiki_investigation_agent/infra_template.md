# infra

monitoring-wiki의 `get_infra`가 돌려줄 클러스터 구성 문서 형식이다. 위키 조사 에이전트(LLM)가 읽고 관측을 티어·노드 그룹에 대응시킨다.
표의 `??`와 예시 값은 실제 구성으로 채운다. 6,000자를 넘으면 뒤쪽이 잘린다.

## 티어 (기준일: 사건 발생일, 데이터 날짜 기준)

| 티어 | 데이터 날짜 | 노드 그룹 | 노드 이름 패턴 |
|---|---|---|---|
| HOT | 최근 13개월 | RC?? | RC??-NN |
| WARM | 13개월 ~ 36개월 | RC17 | RC17-NN |
| WARM-03 (cold) | 36개월 이전 | RC?? | RC??-NN |

- 노드 그룹은 노드 이름의 앞부분이다(`RC17-04` → `RC17`).
- 검색 기간은 query log의 `s_date`~`e_date`(YYYYMMDD), slowlog 쿼리의 range 조건(`gte`/`lte` 등)에서 읽는다.

## 인덱스 → 날짜

- 인덱스 이름에서 데이터 날짜를 읽는 법 (예: `<prefix>-YYYYMM`)

## 구성상 취약점

- 예: WARM은 사양이 낮아 장기간 검색이 몰리면 GC·응답 지연이 생기고 마스터 로그에 node-left로 보인다.
